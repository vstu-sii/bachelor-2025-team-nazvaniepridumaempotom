## 3. Performance Benchmarks

### Текущие показатели прототипа

| Метрика | Значение | Комментарий |
|---------|----------|-------------|
| **Время анализа изображения (Llava)** | 5-8 сек | Зависит от размера изображения и нагрузки |
| **Время анализа текста (Llama 3.2)** | 3-6 сек | Зависит от длины рецепта |
| **Общее время отклика API** | 8-15 сек | Синхронная обработка блокирует другие запросы |
| **Обработка ошибок некорректных файлов** | < 1 сек | Быстрая валидация |
| **Пиковая нагрузка** | 1 одновременный запрос | Синхронная архитектура не поддерживает параллелизм |
| **Узкие места** | Ollama subprocess, синхронные вызовы | Основные точки для оптимизации |

### Целевые показатели для MVP

- **Общее время анализа:** ≤ 15 секунд (95 перцентиль)
- **Время отклика UI:** ≤ 2 секунды
- **Поддержка параллельных запросов:** ≥ 5 пользователей
- **Доступность сервиса:** ≥ 99% в рабочее время

### План оптимизации

1. **Асинхронная обработка (Спринт 5):**
   - Внедрение Celery + Redis для очередей задач
   - WebSocket для статуса обработки

2. **Кеширование (Спринт 6):**
   - Кеширование результатов похожих анализов
   - CDN для загруженных изображений

3. **Оптимизация моделей:**
   - Квантование моделей для уменьшения времени инференса
   - Оптимизация промптов для быстрого ответа

## 4. Security Audit

### Текущее состояние прототипа

- ❌ **Аутентификация пользователей** (отсутствует)
- ❌ **Валидация входных файлов** (базовая, но не полная)
- ✅ **Изоляция AI-моделей** (локальный Ollama)
- ❌ **Rate limiting** (отсутствует)
- ❌ **Логирование безопасности** (отсутствует)
- ✅ **HTTPS для production** (планируется)
- ❌ **Аудит промптов** (отсутствует)

### Основные риски

1. **DoS через ресурсоёмкие запросы:** Большие изображения могут надолго блокировать сервис.
2. **Инъекции через текстовые рецепты:** Пользовательский ввод передаётся напрямую в LLM.
3. **Несанкционированный доступ к данным:** Отсутствие аутентификации.
4. **Уязвимости в зависимостях:** Не проводится регулярный аудит.

### План устранения рисков

1. **Спринт 4:**
   - Валидация размера и типа загружаемых файлов
   - Базовое логирование всех запросов

2. **Спринт 5:**
   - Внедрение JWT аутентификации
   - Rate limiting для эндпоинтов анализа
   - Санитизация пользовательского ввода перед передачей в LLM

3. **Спринт 6:**
   - Регулярный аудит зависимостей
   - Мониторинг подозрительной активности
   - Шифрование чувствительных данных

## 5. AI Quality Metrics

### Качество AI-анализа

| Метрика | Текущее состояние | Целевое значение |
|---------|-------------------|------------------|
| **Согласованность оценок** | ⚠️ (нуждается в тестировании) | ≥ 80% для одинаковых входных данных |
| **Релевантность текстового фидбэка** | ⚠️ (базовые промпты) | Конкретные, выполнимые рекомендации |
| **Успешность распознавания блюд** | ⚠️ (ограниченное тестирование) | ≥ 70% для типичных блюд |
| **Соответствие оценок ожиданиям** | ❌ (нет данных) | >75% пользователей согласны с оценкой (NSM) |
| **Время стабильного ответа** | ⚠️ (вариативно) | < 15 секунд в 95% случаев |

### План улучшения AI-качества

1. **Сбор и анализ данных:**
   - Создание тестового набора из 100+ пар "фото-рецепт-ожидаемая_оценка"
   - Регулярный запуск тестового набора для отслеживания регрессий

2. **Оптимизация промптов:**
   - A/B тестирование разных версий промптов
   - Специфичные промпты для разных категорий блюд

3. **Валидация результатов:**
   - Механизм пользовательского фидбека ("Полезен ли этот анализ?")
   - Ручная модерация примеров для обучения
