## MVP Scope — AI Food Assistant
1. Определение MVP
В состав MVP входят основные пользовательские сценарии (UC-1 - UC-3), необходимые для демонстрации рабочего прототипа:

UC-1: Оценка по новому рецепту: Загрузка фото блюда + текстовый рецепт → получение AI-оценки.

UC-2: Оценка по сохранённому рецепту: Быстрая оценка нового блюда на основе ранее введённого рецепта.

UC-3: Просмотр истории: Доступ к ленте всех проведённых оценок с фото, рецептами и результатами.

Дополнительные системные требования для MVP:
4. Работа с API: Получение и отображение результатов от локальной AI-модели.
5. Временное хранение данных: Сохранение сессионных данных в памяти.

Итог:
Все ключевые use-cases из PRD реализованы в прототипе. Сквозной сценарий работает:
Пользователь → загрузка фото и рецепта → AI-анализ → отображение оценок → сохранение в историю (в рамках сессии).

2. Приоритизация backlog
Поскольку MVP находится на стадии прототипа (Proof of Concept), текущий бэклог состоит из задач по превращению его в полноценное приложение.

Основные направления для развития:
Архитектура и инфраструктура:

Выделение полноценной базы данных (PostgreSQL/SQLite).

Внедрение асинхронной обработки запросов для масштабируемости.

Развертывание на тестовом сервере (Docker).

Качество AI-анализа:

Тонкая настройка промптов для моделей Llava и Llama для более точных оценок.

Реализация системы валидации входных данных (качество фото, структура рецепта).

Пользовательский опыт (UX) и Frontend:

Создание полноценного веб-интерфейса (Next.js) взамен работы только через API.

Реализация адаптивного дизайна.

Добавление визуализации прогресса анализа и результатов.

Безопасность и надёжность:

Реализация системы аутентификации и авторизации пользователей (JWT).

Добавление обработки ошибок и fallback-стратегий при недоступности AI-моделей.

Валидация и санитизация загружаемых файлов.

3. Планирование следующего спринта (Спринт 4)
Цель спринта: Превращение прототипа в рабочий MVP с базовым пользовательским интерфейсом.

Задачи следующего спринта:
Разработка Frontend (Next.js):

Создание страниц: Главная, Загрузка блюда, История.

Реализация компонентов для загрузки файлов, отображения оценок (ScoreDisplay) и истории.

Интеграция с существующим FastAPI бэкендом.

Добавление постоянного хранения данных:

Настройка SQLite базы данных (модели User, Dish, Rating).

Реализация CRUD-операций для работы с рецептами и историей.

Перенос логики хранения из памяти в БД.

Улучшение AI-интеграции:

Оптимизация промптов для получения структурированного JSON-ответа от моделей.

Добавление базовой валидации входных данных (размер фото, длина рецепта).

Базовый UX/UI:

Настройка адаптивной верстки.

Добавление индикаторов загрузки и состояния системы.

4. Управление техническим долгом
На текущий момент выявлены следующие критичные зоны технического долга, которые необходимо устранить для перехода к стабильной версии:

Синхронная обработка AI-запросов: Блокирует сервер при одновременных запросах. Приоритет: Высокий.

Отсутствие постоянной базы данных: Потеря всей истории при перезапуске сервера. Приоритет: Высокий.

Нет фронтенда: Продукт не может быть использован обычными пользователями. Приоритет: Критический.

Отсутствие аутентификации: Нет изоляции данных между пользователями. Приоритет: Средний.

План погашения технического долга:
Спринт 4: Добавление SQLite и базового фронтенда (Next.js).

Спринт 5: Внедрение асинхронной очереди задач (Celery/Redis) и системы аутентификации.

Спринт 6: Улучшение промптов, добавление расширенной статистики и рекомендаций.

Спринт 7: Тестирование, оптимизация и подготовка к демо-запуску.

5. Критерии готовности к Alpha-версии (Demo Day)
Для успешной демонстрации на Demo Day необходимо достичь следующих показателей:

Функциональные критерии:
✅ Пользователь может загрузить фото и рецепт через веб-интерфейс.

✅ Система возвращает две оценки (внешний вид, соответствие рецепту) и текстовый фидбэк.

✅ История оценок сохраняется и отображается в личном кабинете между сеансами.

✅ Все основные компоненты (Frontend, Backend, AI) работают в едином контуре.

Качественные критерии (для демо):
✅ Время отклика системы (от загрузки до результата) ≤ 20 секунд.

✅ Интерфейс интуитивно понятен и не вызывает ошибок у тестовых пользователей.

✅ Система стабильно работает в течение 30-минутной демонстрации без падений.

✅ AI-оценки выглядят правдоподобно и соответствуют загруженным фото/рецептам.

Вывод
Прототип ядра системы успешно реализован.
Доказана работоспособность ключевой технологии: интеграция FastAPI с локальными LLM-моделями (Ollama) для анализа изображений и текста. Бэкенд способен принимать запросы и возвращать сгенерированные AI-оценки.

Текущая оценка готовности к Alpha-демо: 40%

Для перехода к демонстрационной Alpha-версии необходимо:

Критически: Разработать полноценный веб-интерфейс (Next.js) для конечных пользователей.

Важно: Внедрить постоянное хранилище данных (БД) для сохранения истории.

Необходимо: Решить проблему блокировки через асинхронную обработку или очередь.

Приоритеты на ближайший спринт (Спринт 4):

Создание фронтенда и базового UI.

Интеграция с базой данных (SQLite).

Стабилизация работы полного цикла (фронтенд → бэкенд → AI → бэкенд → фронтенд).
