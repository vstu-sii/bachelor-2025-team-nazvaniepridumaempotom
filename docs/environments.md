# Настройка окружений — AI Food Assistant

## 📌 Цель
Документ описывает конфигурацию окружений (Dev, Staging, Demo), управление переменными окружения, стратегию ротации секретов и планы резервного копирования для проекта **AI Food Assistant**.

---

## ⚙️ Окружения

### 🚧 Dev (локальная разработка)

- **Локальный запуск backend:** `python main.py` (FastAPI на порту 8001)
- **Локальный запуск frontend:** `npm run dev` (Next.js на порту 3000)
- **AI-модели:** Локальный Ollama с моделями Llava и Llama 3.2
- **База данных:** Временное хранение в памяти (Python dict) / SQLite для разработки
- **Использование:** Разработка, отладка промптов, тестирование AI-анализа

---

### 🧪 Staging (интеграция и тестирование)

- **Развёртывание:** Docker Compose на тестовом сервере
- **Frontend:** Сборка Next.js для тестирования UI/UX
- **Backend:** FastAPI с подключением к тестовой БД
- **База данных:** PostgreSQL (тестовый инстанс)
- **AI-модели:** Тестовый инстанс Ollama
- **Использование:** Интеграционные тесты, нагрузочное тестирование AI-пайплайна, UX-тестирование

---

### 🎯 Demo (демонстрация MVP)

- **Развёртывание:** Docker Compose на демо-сервере
- **Frontend:** Production-сборка Next.js
- **Backend:** FastAPI с оптимизированными промптами
- **База данных:** PostgreSQL с базовыми бэкапами
- **AI-модели:** Стабильный инстанс Ollama
- **Мониторинг:** Базовый мониторинг доступности и времени отклика AI
- **Использование:** Финальная демонстрация проекта, сбор фидбека

## 🧩 Политика окружений

### **Dev**
- Прямой доступ к `.env` файлам разрешён разработчикам
- AI-модели запускаются локально без ограничений
- Отключены или ослаблены лимиты запросов для тестирования
- Разрешена подробная логирование для отладки промптов

### **Staging**
- `.env` файлы хранятся в зашифрованном виде или в секрет-менеджере
- Включены все проверки безопасности
- Настроены реалистичные лимиты запросов к AI-моделям
- Активно ведётся мониторинг качества AI-ответов
- Используется тестовая база данных, отдельная от продакшена

### **Demo**
- Все секреты хранятся через секрет-менеджер
- Настроен базовый мониторинг доступности сервисов
- Реализованы fallback-стратегии при недоступности AI-моделей
- Включено кеширование частых запросов для улучшения производительности
- Регулярные бэкапы пользовательских данных и истории оценок

## 🔒 Secrets Rotation

### Ключевые секреты проекта:
- **JWT Secret Key** - для аутентификации пользователей
- **Database credentials** - при переходе на PostgreSQL
- **API Keys** - при интеграции с облачными AI-сервисами в будущем

### Политика ротации:
- **JWT Secret Key:** ротация каждые **90 дней**
- **Database пароли:** ротация при каждом значительном обновлении
- Доступ к секретам имеют только:
  - DevOps инженер
  - Tech Lead проекта
  - CI/CD Pipeline для автоматического деплоя

### Хранение секретов:
- **Dev:** Локальные `.env` файлы (исключены из Git через `.gitignore`)
- **Staging/Demo:** GitHub Secrets или HashiCorp Vault
- **Криптография:** Использование современных алгоритмов шифрования

## 💾 Backup и Recovery

### 📦 Backup (резервное копирование)

#### Данные пользователей (при переходе на БД):
- **История оценок:** Ежедневные инкрементальные бэкапы
- **Сохранённые рецепты:** При каждом изменении
- **Профили пользователей:** Еженедельные полные бэкапы

#### AI-конфигурации:
- **Промпты для моделей:** Версионирование в Git
- **Конфигурации Ollama:** Резервное копирование при изменениях
- **Логи AI-анализа:** Хранение в течение 30 дней для анализа качества

#### Конфигурации приложения:
- `.env` файлы (зашифрованные)
- `docker-compose.yml` конфигурации
- Nginx/обратный прокси настройки

### ♻️ Recovery (восстановление после сбоя)

#### Процедура восстановления:
1. **Приоритет 1:** Восстановление сервиса анализа (Ollama + FastAPI)
2. **Приоритет 2:** Восстановление frontend интерфейса
3. **Приоритет 3:** Восстановление пользовательских данных (если есть БД)

#### Порядок действий:
1. Проверка и перезапуск Ollama сервиса с AI-моделями
2. Восстановление FastAPI бэкенда из Docker образа
3. Восстановление Next.js фронтенда
4. Восстановление данных из последней резервной копии (если применимо)
5. Проверка всех API эндпоинтов
6. Smoke-тест полного цикла анализа

#### Smoke-тест после восстановления:
1. Загрузка тестового изображения блюда
2. Отправка тестового рецепта
3. Проверка получения AI-оценок (две числовые оценки + фидбек)
4. Проверка сохранения в историю
5. Проверка отображения результатов в интерфейсе
6. Валидация времени отклика (< 15 секунд)

#### Время восстановления (RTO):
- **Критичный функционал (AI-анализ):** ≤ 30 минут
- **Полное восстановление системы:** ≤ 2 часа
- **Восстановление данных (если применимо):** ≤ 4 часа
